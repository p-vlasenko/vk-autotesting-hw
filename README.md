# ДЗ №6 — паттерны в автотестах генератора квизов

Одиннадцать активных UI-тестов на TypeScript и Playwright и один отключённый учебный
пример `test.skip()`. Проверяют [генератор квизов](https://p-vlasenko.github.io/higher-web-practice-quiz-generator/),
размещённый на GitHub Pages. Для запуска нужен интернет.

В архитектуре используются Page Object, Page Element / Wrapper, Loadable
Component, Chain of Invocations, Value Object, Data Provider и Factory.
Подробное соответствие паттернов коду приведено в [docs/HW-6.md](docs/HW-6.md).

Fixture `generator` в [tests/fixtures.ts](tests/fixtures.ts) создаёт отдельный
Page Object для каждого теста. Хук `beforeEach` открывает его, а сценарий получает
тот же объект через аргументы теста. Основные операции Page Object оформлены как
`test.step()`: в отчёте видны создание квиза, переходы и проверки с понятными
названиями. Большинство шагов сценария записаны последовательными `await`;
короткая цепочка в тесте сохранения демонстрирует Chain of Invocations.

Генератор внешнего приложения показывает активную форму до завершения
инициализации JavaScript. Поэтому его Page Object ожидает выполнение
подключённого entry-модуля, включая top-level await. При доступе к исходникам
приложения готовность лучше выражать состоянием UI: включать элементы формы
после подключения обработчиков.

## Установка

Понадобятся Node.js **26.13.0** и pnpm **10.20.0**.
Команды выполняются из корня репозитория.

Если используете fnm, установите его и подключите к своей оболочке.
Затем выберите версию Node.js из `.nvmrc`:

```bash
fnm install
fnm use
```

Установите pnpm, зависимости проекта и браузер Chromium:

```bash
npm install --global pnpm@10.20.0
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
```

Если на Linux браузеру не хватает системных библиотек:

```bash
pnpm exec playwright install --with-deps chromium
```

## Запуск

Запустить все активные тесты:

```bash
pnpm test
```

Чтобы видеть действия в браузере, используйте `pnpm test --headed`.
Собирать проект или запускать локальный сервер не требуется.

Другие команды:

| Команда | Что делает |
| --- | --- |
| `pnpm check` | Проверяет типы, запускает ESLint и тесты |
| `pnpm typecheck` | Проверяет типы TypeScript |
| `pnpm lint` | Проверяет код через ESLint |
| `pnpm test tests/` | Запускает тесты из каталога |
| `pnpm test tests/quiz.spec.ts` | Запускает тесты из spec-файла |
| `pnpm test --grep 'Прохождение квиза'` | Запускает группу по названию |
| `pnpm test --grep @generator` | Запускает проверки генератора по тегу |
| `pnpm test --grep @storage` | Запускает проверки списка квизов по тегу |
| `pnpm test --grep @quiz` | Запускает прохождение квиза по тегу |
| `pnpm test --list` | Показывает все зарегистрированные тесты |
| `pnpm test --repeat-each=3` | Запускает каждый тест три раза |
| `pnpm exec playwright show-report` | Открывает отчёт последнего запуска |

При падении теста скриншот и трассировка сохраняются в `test-results/`.
HTML-отчёт находится в `playwright-report/`.
В [tests/quiz.spec.ts](tests/quiz.spec.ts) хук `afterEach` прикладывает к отчёту
каждого выполненного теста JSON `test-summary` с названием, фактическим и
ожидаемым статусами и конечным URL.

## Что проверяют тесты

- **Генератор:** три варианта некорректного JSON (`qwe`, `{`, `{"title":}`)
  вызывают закрываемую ошибку; JSON без названия квиза вызывает ошибку структуры.
  Отдельный регрессионный тест с задержанным top-level await проверяет, что
  `open()` ждёт инициализацию обработчика формы и не выполняет entry-модуль повторно.
- **Список квизов:** созданный квиз отображается и сохраняется после перезагрузки.
- **Прохождение:** правильные ответы с одиночным и множественным выбором дают
  максимальный результат; ошибка показывает пояснение и учитывается в результате.
  Для multiple отдельно проверяются неполный правильный набор, лишний
  неправильный вариант и набор только из неправильного варианта.

Сценарии находятся в [tests/quiz.spec.ts](tests/quiz.spec.ts), тестовые данные —
в [tests/data/quiz.ts](tests/data/quiz.ts). Работа со страницами вынесена
в [tests/pages/](tests/pages/): там хранятся локаторы, действия и проверки.
Каждый тест запускается в отдельном контексте браузера и сам создаёт свои данные.
