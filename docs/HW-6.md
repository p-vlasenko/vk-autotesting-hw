# ДЗ №6. Написание автотестов с паттернами проектирования на TypeScript

## Описание

### Цель

Сформировать навыки проектирования архитектуры автоматизированных тестов с использованием шаблонов проектирования, обеспечивающих расширяемость, повторное использование и сопровождаемость тестового кода.

### Задание

Продолжаем работу с проектом на Node.js, pnpm и TypeScript в строгом режиме с использованием Playwright Test.

Усложняем проект за счет использования паттернов. Добавляем 1–2 теста или переписываем имеющиеся. В коде должны активно использоваться базовые паттерны:

- Page Object;
- Page Element / Decorator / Wrapper;
- Loadable Component;
- Chain of Invocations;
- Value Object.

Также нужно использовать минимум один дополнительный паттерн:

- Data Provider;
- Factory;
- Data Registry;
- Promise;
- другие подходящие паттерны.

## Как выполнено на TypeScript

Существующие семь активных тестов переписаны на новую архитектуру без изменения их проверок. Отключённый учебный пример из ДЗ №5 сохранён. Используются фабричные функции и структурные типы TypeScript; классы и декораторы языка не требуются.

| Паттерн | Реализация |
| --- | --- |
| Page Object | `createGeneratorPage()`, `createQuizzesPage()` и `createQuizPage()` инкапсулируют локаторы, действия и проверки соответствующих страниц |
| Page Element / Wrapper | `createPageElement()` оборачивает Playwright `Locator` и предоставляет типизированные действия и автоматически повторяемые проверки |
| Loadable Component | Общий контракт `LoadableComponent<T>` с `waitForLoaded()`; страницы и карточка квиза ждут характерные элементы перед дальнейшими действиями |
| Chain of Invocations | Методы возвращают Promise текущего Page Object или следующей загруженной страницы; тесты объединяют шаги через `.then(currentPage => currentPage....)` |
| Value Object | `Quiz` и вложенные структуры являются неизменяемыми структурными данными; `questionCountText()` вычисляет производное значение |
| Data Provider | Таблицы `invalidJsonCases` и `scenarios` регистрируют отдельные тесты для каждого набора параметров |
| Factory | `createQuiz()` создаёт согласованные тестовые данные, а фабрики `create...Page()` создают Page Object |

`GeneratorPageObject.addQuiz()` возвращает загруженный `QuizzesPageObject`,
а `QuizzesPageObject.startQuiz()` — загруженный `QuizPageObject`. Поэтому переход
между страницами не требует ручного создания следующего объекта в тесте.
Отправка некорректных данных выполняется отдельно через `submitQuizData()`:
после неё сценарий остаётся на генераторе и проверяет модальную ошибку.

Карточка квиза вынесена в `createQuizCard()` и использует тот же контракт
загрузки. Проверки описания и количества вопросов остаются мягкими, как в ДЗ №5.
Все UI-проверки используют автоматически повторяемые утверждения Playwright.

Нативные Promise используются как механизм цепочек, но не выделяются в отдельную
демонстрацию дополнительного паттерна: дополнительное требование выполняют
Data Provider и Factory. Data Registry и собственная реализация Promise не нужны.

Запуск и отчёты описаны в [README.md](../README.md). Как и раньше, каждый тест
выполняется в отдельном контексте браузера и сам создаёт свои данные.
