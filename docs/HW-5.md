# ДЗ №5. Написание автотестов с использованием Playwright Test и TypeScript

Домашнее задание

Описание:

## Цель:

Сформировать навыки построения надежных автоматизированных тестов за счет корректного использования локаторов пользовательского интерфейса, возможностей Playwright Test и современных средств автоматизации веб-тестирования.

## Задание:

Продолжаем работу с проектом на Node.js, pnpm и TypeScript в строгом режиме с использованием Playwright и паттерна Page Object.

1) Нужно использовать возможности Playwright Test, соответствующие аннотациям JUnit из исходного задания.

Базовые возможности (активно используем):

- `test()` + `test.beforeEach()` + `test.afterEach()` — объявление тестов, подготовка и действия после каждого теста (`@Test`, `@Before`, `@After`).
- Теги через `tag` и выбор тестов через `--grep` (`@Tag`).
- `test.skip()` с указанием причины пропуска (`@Disabled`).
- Понятные названия тестов и групп (`@DisplayName`).
- Несколько последовательных `await expect.soft(...)` — сбор нескольких ошибок проверок без остановки на первой из них (`assertAll()`). Тест при этом считается упавшим, если хотя бы одна проверка не прошла.
- Запуск тестов по каталогам, spec-файлам и группам `test.describe()` — аналог запуска по пакетам и классам.
- Таймауты для тестов в конфигурации и для отдельных тестов или групп.

## Дополнительные (хорошо бы попробовать использовать):

- Генерация отдельных тестов из данных при загрузке spec-файла — ближайший функциональный аналог `@TestFactory`. Прямого аналога динамических тестов JUnit в Playwright Test нет: тесты регистрируются до начала выполнения, каждый получает отдельное название и результат.
- Параметризованные тесты: таблица параметров и регистрация `test()` для каждого набора данных (`@ParameterizedTest`). Генерация тестов из таблицы может одновременно демонстрировать оба подхода.
- Вложенные группы `test.describe()` (`@Nested`).

1) Имеющиеся автотесты можно модифицировать и дописывать, а также писать новые. Количество автотестов на ваше усмотрение, исходя из задания.

## Как выполнено на typescript

В коде `test` импортирован как `it`, а `describe` взят из `it`.

| Требование исходного задания | Реализация |
| --- | --- |
| `@Test` | `it()` с описательным названием каждого сценария |
| `@Before` | `it.beforeEach()` открывает генератор перед каждым тестом |
| `@After` | `it.afterEach()` прикладывает сведения о выполнении |
| `@Tag` | Теги групп `@generator`, `@storage`, `@quiz` и запуск через `--grep` |
| `@Disabled` | Отдельный `it.skip()` с причиной пропуска в аннотации `skip` |
| `@DisplayName` | Русские названия тестов и вложенных групп в отчёте |
| `assertAll()` | `expect.soft()` проверяет описание и количество вопросов карточки, собирая обе ошибки |
| Запуск по пакетам/классам | Выбор каталога, spec-файла и группы командами выше |
| Таймауты | 30 секунд на тест и 5 секунд на проверку в конфигурации; 60 секунд на тест группы прохождения через `it.describe.configure()` |
| `@TestFactory` | Цикл регистрирует три самостоятельных теста ошибок синтаксиса при загрузке spec-файла |
| `@ParameterizedTest` | Таблица сценариев прохождения задаёт первый ответ, пояснение и ожидаемый результат |
| `@Nested` | Вложенные группы: генератор → валидация JSON → синтаксис / структура |

Генерация тестов при загрузке файла — ближайший функциональный аналог
`@TestFactory`; прямого аналога динамических тестов JUnit в Playwright Test нет.
Каждая строка таблиц становится отдельным тестом со своим результатом.
Все UI-проверки используют автоматически повторяемые утверждения Playwright.
Мягкие проверки выполняются после обязательной проверки URL и наличия
единственной карточки; любая их ошибка делает тест упавшим.

Отключённый пример создания карточки демонстрирует `@Disabled`; это поведение
проверяется активным тестом сохранения. В отчёте указана причина пропуска.
